Move a file from a screen to a phone with only light.

QRStream plays any file as a video of QR codes. A phone films the screen and rebuilds the file, checks it with SHA-256 and keeps it. No Wi-Fi, no Bluetooth, no cable, no pairing, no account, no upload.

Try it now: open Send on a computer and Receive on a phone, tap Use a demo picture, point the camera.

What it is

A one-way data link

The sender only shows pictures; the receiver only looks. Nothing travels back, so there is nothing to pair, connect or attack over a network.

Loss does not matter

Every frame carries fresh fountain-coded data. Blur, glare or a missed frame costs a little time, never a restart. Any set of symbols about 2 % larger than the file rebuilds it.

Checked and private

Every frame has a CRC-32, the whole file a SHA-256. The file stays in the receiving browser; it can be opened, saved, or handed to the phone's own share sheet.

How to use it

  1. 1

    Pick a file on the sender

    Open Send on the screen that holds the file (a kiosk, a lab PC, a laptop) and choose a file, drop it, paste a copied picture, or type some text.

  2. 2

    Film the screen

    The stream starts with a link code: scan it with the phone's camera app. The receiver opens and starts its camera by itself (tap Start Camera if asked). The same code stays in the corner of the sender for phones that arrive late. Hold still so the whole code is in the frame.

  3. 3

    Open, save or share

    The percent climbs on the phone. When the file checks out it is shown right in the camera box with Open, Save, Share, Email. Share uses the phone's own share sheet (AirDrop, Messages, WhatsApp, Files, Drive...).

No camera at hand? Record the screen with any phone, then use Use a Video of the Code on the receiver.

Use cases

Isolated and secure systems

Take a report or log off a machine that must never join a network, without USB sticks that carry malware the other way.

Kiosks, HMIs and embedded screens

Industrial panels, CCTV/NVR monitors, medical carts and point-of-sale screens that have a display but no friendly way to export.

Field work with no signal

Mines, ships, plants, basements and remote sites: the receiver works offline after one visit (it installs as a web app).

Evidence and incident capture

Hand a camera still, a short clip or a PDF to an inspector's phone on the spot, with a SHA-256 check and a short check code on both screens to compare.

Guests and BYOD

Give a visitor a file without giving them your Wi-Fi password, an app, or an email address.

Demos, classrooms, events

Put a handout, a config or a ticket on a projector; everyone in the room films it at once. One sender, any number of receivers.

When to use it, and when not

Good fit

  • Files up to a few MB: pictures, short clips, PDFs, Office files, logs, configs, keys.
  • There is a screen, a camera, and no shared network, or a network you must not use.
  • You want zero setup on the sender beyond a web page.
  • Many receivers at once.

Use something else

  • Large files (tens of MB and up): even at the peak of about 128 KB/s a 10 MB file needs well over a minute, and longer on a small screen.
  • You need the phone to send back to the screen: this link is one way by design.
  • The screen is very small or the camera very poor: use a lower density, or a cable.
  • Secret data on a screen others can film: anyone with a camera in view can receive it too.

Specifications

CodeQR Model 2 (ISO/IEC 18004), alphanumeric mode, error level L, versions 15 to 40; own encoder
Payload textBase45 (RFC 9285): 2 bytes in 3 QR alphanumeric characters
Erasure codeSystematic random linear fountain over GF(2) in generations of 1,024 blocks, interleaved source order, incremental Gaussian elimination with bounded memory; 142-byte symbols fixed across densities. Measured overhead 1 to 4 % at 20 to 50 % frame loss
Frame20-byte header (magic, version, stream id, length, seed, CRC-32) + up to 20 symbols = 2,840 bytes per code at QR v40; 1 to 8 codes per screen, in one or two rows
Smart modeThe sender measures its own screen, picks the densest layouts that stay readable, and weaves fast and safe frames into one stream (A A A B A A B C). The phone coaches the user only when needed. No settings.
ThroughputRaw per code: v40 at 15/s ≈ 42 KB/s. Up to 8 codes per screen (two rows of four) and up to 30 screens per second (manual Extreme). Smart mode on a Full HD screen: up to 81 KB/s; on a 2560 × 1440 screen: up to 137 KB/s. Measured through the camera path with a camera simulator (not yet on physical phones): 300 KB random in 4.5 s with Smart on a 1080p screen (65 KB/s); 128 to 137 KB/s at 3 codes and 30 screens/s; a 334 KB log in 0.9 s thanks to gzip
IntegrityCRC-32 per frame, CRC-32 per chunk to locate damage, SHA-256 of the file
ReaderOwn QR reader in Web Workers: local-threshold binarisation, finder search, timing-pattern sizing, incremental alignment-grid lock with least-squares homography, per-cell maps, Reed-Solomon (Berlekamp-Massey, Forney). About 25 ms for three v40 codes in a 1080p picture
LimitsSender 10 MB; receiver refuses streams over 16 MB, stops inflating at 64 MB, and bounds decoder memory
BrowsersSender: any modern browser. Receiver: Chrome, Edge, Firefox, Safari 16.4 or later, with a camera; https or localhost. PDFs open in the device's own viewer

Security and privacy

  • No server: both pages are static files. The receiver makes no network request with your data (strict Content-Security-Policy, connect-src 'self').
  • Received files are typed defensively: HTML, SVG, XML and scripts are opened as plain text, never run in the page.
  • Forged frames are rejected (magic, CRC-32), a forged length over 16 MB is ignored, and previews stop inflating at 4 MB.
  • Zero third-party code: the QR encoder and reader, the erasure code and the previews are all written in this project. Nothing is loaded from a CDN.
  • The SHA-256 proves the file arrived without errors; it does not prove who showed it. Compare the 8-character check code on both screens when that matters. Files save by themselves only for common picture, video, audio, PDF and text types; anything else waits for a tap.
  • Optical links are visible: treat the screen like a printout. Anyone filming it can read it.

FAQ

Does the phone need internet?

Only once, to load the receiver. After that it starts from its offline cache. The transfer itself never uses a network.

Why do some codes look different?

There is no back channel, so the sender cannot ask the camera what it reads best. Smart mode mixes the fastest readable layout with safer ones in a single stream; every frame carries useful data, so a good camera runs near full speed and a weak one still finishes. Symbols have a fixed size, so nothing received is ever wasted.

How do I make it faster?

Nothing to set: Smart mode adapts to the screen. A larger or wider screen carries more codes at once; fill the camera view with it and avoid glare. Text-like files are compressed first automatically. For lab conditions there are manual Extreme levels (20 and 30 codes per second).

Can I send text or several files?

Text: open Send text instead on the sender, or paste. Several files: put them in one zip file first.

It is stuck or slow. What do I check?

Fill the camera view with the screen, hold still, and tilt a little to remove glare. Turn the screen brightness up. If only the slower codes get through, move closer. If the phone looked away, just point it back: nothing is lost.

Can I save to the photo library on iPhone?

A web page cannot write there itself. The receiver opens the iOS share sheet, where you choose Save Image, Save Video or Save to Files.

Can I embed the sender in my own product?

Yes. core/qrtx.js is one dependency-free file; see the README for the API. MIT licence.
